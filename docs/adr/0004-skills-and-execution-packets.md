# Skill procedures and bounded execution packets

Status: accepted.

Keep eight named agents for conversation, ownership and selected runtime/model configuration; define reusable work procedures in twelve skills. Load only applicable procedures and absent instructions. This supports direct specialist consultation and independent contexts without copying full methods into every role.

Separate tracker identity, execution packet, review unit and PR unit. Bounded related tasks may share worker/reviewer context while preserving each task's criteria, dependencies, evidence and status. Respect explicit per-task/team/delivery choices and intermediate gates. Grouping never implies stacking or consolidation.

Tester defaults to independent read-only case design when enabled; test-author mode remains an explicit choice. One writer owns production; tests stay with Developer unless explicitly assigned. Prompt orchestration and optional prose project preferences remain; no scheduling service or global billing integration is added.

Tradeoff: smaller repeated context can reduce overhead, but larger packets can increase coupling or obscure individual failures. Bound packet scope and split at incompatible ownership, risk, context growth or delivery boundaries. Verify by representative runtime scenarios rather than assumed token savings.
