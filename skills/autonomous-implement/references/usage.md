# Usage and limits

Record one row per Ticket/stage: model/provider, elapsed time, dispatch/candidate count, review pass, input/output/cached tokens, cost/currency, usage source and outcome. Use agreed run-record location, default .scratch/runs/<run-id>.md.

Use actual runtime/provider data; unavailable values remain unknown. Distinguish model time from tool/wait time. Exclude secrets/private reasoning. Total only compatible known units/currencies; disclose missing coverage. Inspect repeated reads, handoffs, failures and repair rounds before attributing cost.

Check behavioral proposal/dispatch/review bounds before dispatch. Monetary ceilings are advisory unless runtime exposes reliable metering/enforcement; state this before execution. Stop new dispatches at observed bounds, preserve work and request a specific extension. Do not claim automatic billing integration or hard dollar caps.
